# أثر — معرض مشاريع بتصميم مستلهم من رتال

المشروع يحتوي React + Vite في المجلد الأساسي، والباك إند Node.js + Express + MongoDB داخل `backend`.

## تشغيل أول مرة

تحتاج Node.js 22.12 أو أحدث وMongoDB محلي يعمل على 27017، أو رابط MongoDB Atlas.

افتح Terminal داخل مجلد `Athar`:

```bash
cd backend
npm ci
npm run setup
```

افتح `backend/.env`: رابط MongoDB الافتراضي هو `mongodb://127.0.0.1:27017/real_estate`. لو تستخدم Atlas ضع رابطك مكانه. أمر setup يولد مفتاح إدارة عشوائي خاص بك ويحفظه في هذا الملف دون طباعته. لا ترسل الملف أو المفتاح للآخرين.

ثم:

```bash
npm run seed
npm run dev
```

اترك Terminal مفتوحًا. افتح Terminal ثاني داخل `Athar`:

```bash
npm ci
npm run dev
```

افتح `http://localhost:5173`، والباك إند يعمل على بورت 5000.

## الربط المنفذ

- قائمة المشاريع من `GET /api/projects` بدل البيانات المحلية.
- بحث بالاسم وفلاتر النوع والمدينة والحالة، وترقيم الصفحات من الخادم.
- تفاصيل المشروع من `GET /api/projects/:slug`.
- الوحدات من `GET /api/projects/:id/units` مع صفحات.
- نموذج الاسم والجوال والبريد والرسالة يرسل `POST /api/inquiries`؛ النجاح يظهر بعد استجابة الخادم فقط.
- إضافة المشروع ترسل `POST /api/projects` بمفتاح الإدارة الذي تدخله يدويًا وقت الإضافة؛ لا يوجد مفتاح داخل كود الفرونت أو localStorage.
- حالات تحميل وخطأ وإعادة محاولة ونتائج فارغة، دون الرجوع لبيانات وهمية عند فشل الاتصال.
- تفعيل Tailwind لأن التصميم المرفق يستخدم utility classes دون وجود Tailwind في إعداداته.

عدّلت حقول العرض لتطابق الباك إند: `name` بدل `title`، `_id` بدل `id`، و`location.address`، ونوع العقار وحالته وعدد الوحدات والسعر. حقول سنة التنفيذ والعميل ومساحة المشروع غير موجودة في الموديل السابق، فلم يتم اختراع قيم لها. حافظت على اسم أثر وشكل الصفحة الأساسي. ملف mockProperties القديم محفوظ لكنه لم يعد مصدر بيانات التطبيق.

المشاريع الثمانية والوحدات الـ48 تجريبية، وليست بيانات أو أسعار شركة رتال. الصور placeholders. إذا أردت عرض أعمالك الفعلية، أضفها من نموذج الإضافة مع روابط صورك.

## إضافة مشروع

اضغط «رفع مشروع جديد» أو «أضف عقارك»، أدخل المفتاح من `backend/.env` ثم بيانات المشروع كاملة. اسم الرابط slug بالإنجليزية مثل `jeddah-villa-01`، ويجب أن يكون فريدًا. يمكن إدخال رابط HTTP/HTTPS للصورة أو رفع صور من الجهاز؛ أول صورة مرفوعة تصبح الغلاف وباقي الصور تظهر في معرض تفاصيل المشروع.

## التصميم ورفع الصور

التصميم الجديد مستلهم من تكوين موقع رتال: صورة افتتاحية كاملة مع قائمة شفافة وسلايدر مشاريع، أقسام بيضاء واسعة ولمسات بنية، معرض مشاريع بصور كبيرة، قسم للرؤية وتذييل جديد. الهوية والنصوص باسم أثر. لم ننسخ شعار رتال أو بياناتها أو صورها. الصورة الافتتاحية الاحتياطية من Unsplash للتوضيح فقط وليست من أعمالك؛ بمجرد إضافة المشاريع تظهر صورها في السلايدر تلقائيًا. لا يتم عرض مشاريع وهمية تلقائيًا عند فشل API.

- زر «رفع مشروع جديد» يفتح نموذج الإدارة.
- اختر حتى 10 صور بصيغة JPEG / PNG / WebP، كل صورة حتى 8 ميجابايت.
- الصور تُفحص بمحتواها الفعلي ثم يعاد ترميزها WebP، وأسماء الملفات عشوائية.
- `POST /api/uploads` محمي بمفتاح الإدارة. يرجع مسارات الصور، ثم تحفظ مع المشروع في `image` و`gallery`.
- مجلد الصور الدائم هو `backend/uploads`. لا تمسحه عند تحديث الكود؛ ضعه على قرص دائم عند النشر وخذ نسخة احتياطية منه مع MongoDB. الأقراص المؤقتة في بعض منصات الاستضافة ستفقد الملفات عند إعادة التشغيل.
- رفع الصور وحفظ المشروع عمليتان منفصلتان؛ فشل حفظ المشروع بعد نجاح الرفع قد يترك صورًا غير مرتبطة داخل مجلد uploads، تحتاج تنظيفًا إداريًا لاحقًا. الصور المنشورة عامة للزوار وليست تخزينًا خاصًا.
- إعداد Vite يوجّه `/api` و`/uploads` للباك إند في التطوير. عند فصل الاستضافة يحسب الفرونت رابط الصور من `VITE_API_URL`.
- جميع روابط القائمة تعمل داخل أقسام الصفحة. الاستفسار يتم من تفاصيل المشروع.
- الربط يحتفظ بموديلات العقارات السابقة؛ إذا كان المشروع للعرض فقط دون تسعير يمكنك إدخال 0 للسعر وعدد الوحدات. بطاقات المعرض تركز على الصور والاسم والمدينة، والتفاصيل تعرض بيانات الموديل.

هذه طريقة إدارة بسيطة بمفتاح مشترك، وليست نظام مستخدمين وتسجيل دخول. لا يوجد في هذه النسخة واجهة لإدارة الاستفسارات أو تعديل وحذف المشاريع؛ مساراتها المحمية موجودة بالباك إند كما في الطلب الأصلي. زر الاستفسار لا يحجز وحدة أو يغيّر حالة بيعها.

## الإعدادات والنشر

ملف الفرونت `.env` يحتوي:

```dotenv
VITE_API_URL=/api
```

Vite يوجه `/api` إلى `http://127.0.0.1:5000` في التطوير فقط. عند نشر الفرونت على استضافة منفصلة غيّر `VITE_API_URL` لرابط الباك إند الحقيقي المنتهي بـ `/api`، ثم أعد `npm run build`. أضف عنوان الفرونت إلى `CORS_ORIGIN` في إعدادات الباك إند. `npm run preview` يعرض build وليس بديلًا عن تشغيل الباك إند أو إعداد reverse proxy للإنتاج.

لا تضع `ADMIN_API_KEY` أو `MONGODB_URI` في أي متغير يبدأ بـ `VITE_`. الاستفسارات تعمل دون مفتاح إدارة. لم يتم نشر المشروع على الإنترنت.

## التحقق

```bash
npm test
npm run build
npm run lint
```

نجحت 3 اختبارات React داخل jsdom مع محاكاة ردود HTTP: عرض البيانات، إرسال الفلاتر، التفاصيل والوحدات، حمولة الاستفسار ومعرف المشروع، حمولة الإضافة والأرقام ومفتاح الإدارة، وإظهار الأخطاء وإعادة المحاولة. نجح البناء. أضيف اختبار رفع ملفات من نموذج الإدارة ثم حفظ روابط الغلاف والمعرض. ونجحت 3 اختبارات مستقلة للباك إند، منها اختبار HTTP فعلي لرفع صورة وتحويلها وحفظها واسترجاعها ورفض ملف مزيف دون الاحتياج لقاعدة البيانات.

في الباك إند نجح اختبار التحقق والحماية، لكن اختبار MongoDB الكامل تعذر لأن البيئة رفضت تشغيل عملية MongoDB (exit 100). المتصفح المنفصل لم يتمكن من الاتصال بالخادم المحلي؛ لم يكتمل فحص بصري للواجهة الجديدة. تم فحص المرجع البصري على موقع رتال نفسه. شغّل `cd backend` ثم `npm test` على جهاز يسمح بتشغيل MongoDB. اختبارات الفرونت لا تثبت الحفظ الفعلي في قاعدة البيانات.
